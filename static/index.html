// 01 capture
POST /api/memories
validate episode fields
→ connect project + outcome
01
Capture. A planner enters the project, agent, decision, incident and lesson. RecallOS validates the fields before writing the episode.

    
// 02 write
POST /api/memories
CREATE (a:Agent {name:$agent})
CREATE (s:Session)-[:RECORDED]->(d:Decision)
LINK decision → incident → lesson
02
Write. FastAPI writes typed nodes and relationships to the selected FalkorDB graph. FalkorDB remains the source of truth when the browser session ends.

    
// 03 traverse
MATCH (s:Session)-[:RECORDED]->(d:Decision)
-[:FOR_PROJECT]->(p:Project)
RETURN s, d, p
03
Traverse. A project or detail query follows connected session, decision, incident, lesson and project nodes in the active workspace.

    
// 04 explain
GET /api/recall?q=…
query project, decision, incident, lesson
→ return connected episode fields
04
Explain. The explorer shows stored relationships directly. Recall returns the connected episode fields that match your project or search text.

    
// 05 hand off
POST /api/handoffs
carry latest lesson + task
receiver acknowledges handoff
05
Hand off. The receiving agent can read its pending queue and acknowledge work. Workspace selection chooses a separate graph; this demo does not provide authentication.

Planner and Support agents share the same FalkorDB workspace. Each later session can retrieve the connected decision, incident and lesson.

    
    

      

CYPHER recall
MATCH (s:Session)-[:RECORDED]->(d:Decision)-[:FOR_PROJECT]->(p:Project),
(d)-[:LED_TO]->(i:Incident)-[:PRODUCED]->(l:Lesson)
WHERE toLower(p.name) CONTAINS toLower($term)
OR toLower(d.text) CONTAINS toLower($term)
OR toLower(i.text) CONTAINS toLower($term)
OR toLower(l.text) CONTAINS toLower($term)
RETURN p.name, d.text, i.text, l.text
ORDER BY s.created_at DESC LIMIT 12
